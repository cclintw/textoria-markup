Textoria Markup：文本實體標註工具

將實體詞表、關鍵詞或文字規則套用到文本，建立可依章節閱讀、查看實體與核對前後文的標註閱讀頁。透過 Codex 對話修訂標註，再匯出成果或發布供他人閱讀。

適合已有參考詞表、需要逐處核對名稱的文本研究。沒有詞表時，可搭配 Textoria Entity Extractor 建立參考詞表，再進行標註。

特色

  • 多種標註來源：組合使用實體詞表、關鍵詞清單、文字規則與 AI 提取參考詞表。
  • 章節閱讀：保留文本階層，以顏色區分實體類型。
  • 實體與前後文：依類型瀏覽名稱，查看出現段落與 KWIC，定位原文。
  • 對話修訂：指定單次出現、段落、章節或全書，新增、刪除或調整標註。
  • 詞表重用：保存修訂後的詞表供後續工作參考。
  • 成果匯出：提供單檔 HTML、詞表、DocuSky 詮釋資料與 DocuXML，也可搭配 Sites 發布網站。

安裝與啟動

需要支援本機 Skill 的 Codex。

透過 Codex 安裝

在 Codex app 開啟工作專案，將下列指令貼到對話中送出：

$skill-installer --repo cclintw/textoria-markup --path .agents/skills/textoria-markup --dest .agents/skills

安裝完成後，在下一回合開始使用。

手動安裝

  1. 開啟 GitHub 專案頁面，選擇 Code → Download ZIP。
  2. 解壓縮後，找到 .agents/skills/textoria-markup/ 資料夾；必要時開啟顯示隱藏檔案。
  3. 將整個 textoria-markup 資料夾及隨附檔案複製到工作專案的 .agents/skills/；目標目錄不存在時先建立。

安裝後的入口檔案為工作專案內的 .agents/skills/textoria-markup/SKILL.md。

使用方式

1. 提供文本與章節

在 Codex 工作專案上傳 TXT、Markdown、HTML，或指定正文欄位的 CSV，也可提供本機路徑。PDF 與圖片需先轉為文字並核對辨識結果。確認文獻集位置後，核對工作稿與章節預覽；可調整 Markdown 標題或用對話說明章節安排。

2. 選擇標註來源

已有詞表時，上傳詞表並送出：

請依上傳的詞表標註全文。

需要先建立詞表時，可要求搭配 Textoria Entity Extractor：

請由 AI 自動提取實體詞表，並完成全文標註。

也可提供具體規則：

請將「名曰」之後、逗號之前的二至六字標為人物，不跨句號或段落。

3. 閱讀與修訂

開啟閱讀頁，從左側實體清單或正文標註核對出現位置。使用實體或段落旁的複製按鈕，將定位資訊貼回 Codex，說明要修改的範圍。

請將這一處的類型改為地名，只修改這次出現。

新增標註時，反白未標註文字並按「＋」，再將複製資訊貼回對話。頁面按鈕只複製定位資訊，送出要求後才由 Codex 更新成果。

4. 匯出與分享

直接要求匯出，或點閱讀頁頂端的匯出圖示，將複製的指令貼回 Codex。發布網站可使用地球圖示複製指令，需具備可用的 Sites。

常見問題

可以匯出哪些成果？

詞表 CSV／JSON 可檢查與重用標註資料；單檔 HTML 保留章節導覽、實體清單與前後文查找；DocuSky 詮釋資料 CSV／Excel 保存標題、作者、年代等資訊，搭配 DocuXML 使用。

詮釋資料表就是批次標記詞表嗎？

兩者用途不同。詮釋資料表描述文獻；批次標記詞表列出待標記的實體名稱。

閱讀頁需要啟動伺服器嗎？

閱讀頁可直接以本機瀏覽器開啟。文獻集保存在工作專案的 textoria-markup/collections/，分別保存原檔、工作稿、標註資料與匯出成果。

修改 Markdown 會更新既有標註嗎？

正式標註建立後，修改先前的工作稿不會自動更新標註；後續修訂需透過 Codex 處理。現階段也不支援將新文件追加到既有文獻集，新文本需另建文獻集。

支援重疊標註嗎？

部分重疊名稱無法同時顯示，目前不支援任意巢狀或交錯標註。AI 詞表與文字比對仍可能漏項或誤標，須對照原文核對。

網站會隨修訂自動更新嗎？

網站預設為私人，發布內容包含全文與標註。修訂後需再次發布，才能更新線上版本。
